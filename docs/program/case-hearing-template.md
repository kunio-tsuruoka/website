# 事例化ヒアリングテンプレート（発注判断の裏側）

作成: 2026-08-17
目的: 事例を「課題→実装→結果」で終わらせず、**顧客が何を判断材料に発注したか**を残す。
検討中の見込み客が最も知りたいのは技術ではなく「自分と同じ立場の人が、何と比べて、何が不安で、なぜここに決めたか」。

## 運用ルール

- **案件クローズ時・事例化の許諾を取るタイミングで、必ずこのヒアリングを行う**
- 取れた事実だけを載せる。推測・創作で埋めない（`decision` フィールドは任意）
- 記載先: `/case-studies`（case-studies.astroのdecision）と `src/data/service.ts` の該当caseStudies.decision
- 「他社では○○が不安だったが、Beekleはプロトタイプを先に見せてくれたので発注判断できた」型の
  生の声が取れたら最優先で採用し、可能なら /testimonial にも短い逐語引用として載せる

## ヒアリング項目（5問）

1. **検討前の悩み**: このプロジェクトを考え始めたとき、社内では何に一番困っていましたか？
2. **比較した選択肢**: 何社（または内製・ノーコード・オフショア等の何手段）と比較しましたか？価格や条件の差はありましたか？
3. **不安だったこと**: 発注を決める前、何が一番不安でしたか？（失敗リスク、要件の複雑さ、費用、社内説明…）
4. **なぜBeekleか**: 最終的にBeekleに決めた理由は何でしたか？他社より高かった/安かった場合、それでも決めた理由は？
5. **決裁に効いた情報**: 社内の決裁を通すとき、どの情報（プロトタイプ、見積内訳、事例、体制…）が一番効きましたか？
